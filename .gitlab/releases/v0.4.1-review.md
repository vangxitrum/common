## 1. `Metrics: false` no longer means no metrics - medium

`postgres/monkit.go:204`. The `Metrics: false` gate was added to
`TraceQueryEnd` only. `TraceBatchStart`/`TraceBatchEnd` (204),
`TraceCopyFromEnd` (221), `TracePrepareEnd` (247), `TraceConnectEnd` (264) and
`TraceAcquireEnd` (287) still call `Observe`/`failed` unconditionally.

Since `OpenWith` now installs the tracer when
`config.Metrics || config.wantsQueryLog()` (`postgres/postgres.go:344`), a pool
configured `Metrics: false, LogQueries: true` emits `postgres_batch`,
`postgres_batch_length`, `postgres_copy_from`, `postgres_connect`,
`postgres_acquire` and all five `*_failed` events. That contradicts both the
config field and the new comment "The tracer is also installed for query
logging alone, and then records nothing."

**Fix:** gate the other five the same way `TraceQueryEnd` is gated.

## 2. `Get` overwrote a value `Add` had just seeded - medium, FIXED

`lrucache/cache.go:244`. The rewritten `add` built the entry without
`loaded: true` and left its `sync.Once` unused, so `Get` on that key took the
`default:` branch, ran `state.once.Do(fn)` and replaced the inserted value.
Reproduced: `Add(ctx, "k", "added")` then `Get(ctx, "k", fn)` returned
`"filled"`, and the cache then held `"filled"`.

For an `AddUntil` entry this also discarded the expiry it was added with - and
`AddUntil` + `Get` is exactly the pattern the new README section recommends and
the pattern the aioz-stream link cache is being migrated onto, so it would have
re-minted a ticket on every read.

`loaded: true` alone is not sufficient: `Get` waits on the once whatever
`loaded` says. The insert now spends the once (`state.once.Do(func() {})`) and
sets `loaded`, with a test covering `Add` + `Get`, `AddUntil` + `Get`, and a
fill that does happen once the entry is inside its margin.

## 3. `group=db` is dropped from db documents - low/medium

`logger/elasticsearch.go:440`. `setDBField`'s
`case "group": return true // the marker itself is not a field` drops the
`group` attribute from db-group documents entirely. Every other record group
keeps `group` in `labels.group` or `log.extra.group`, so a Kibana filter
`labels.group : "db"` matches nothing for exactly the records the README says
"carry `group=db`".

**Fix:** map it (`event.category` or `labels.group`), or stop documenting it as
carried. Worth settling before the paired `aioz-monitor` template change ships,
since that is the same window.

## 4. A failed statement's error text is unmapped - low

`postgres/querylog.go:86`. A failed query is logged under the key `err`, but
the Elasticsearch sink maps `case "error":` to ECS `error.message`
(`logger/elasticsearch.go:345`) and `err` is not in `setDBField` either, so the
error text lands in `log.extra.err` - stored, unmapped, unsearchable - while
the README says the db fields are mapped. Use `"error"` as the key, or add an
`err` case to the sink.

## 5. The statement is rewritten even when the level is off - low

`postgres/querylog.go:73`. `cleanStatement` (`strings.Fields` +
`strings.Join`, plus `attrsOf`'s allocation) runs on every query before
`t.log.LogAttrs` decides the level is disabled. With `LogQueries: true` and the
handler at `info`, each query pays a full statement rewrite and slice build and
emits nothing. Guard with `if !t.log.Enabled(ctx, level) { return }`.

## 6. The 2,048-character cap can cut a rune in half - low

`postgres/querylog.go:124`. `statement[:maxStatementLen]` slices by byte, so a
multi-byte rune straddling offset 2048 - a non-ASCII string literal, a quoted
identifier - is cut mid-rune. The invalid UTF-8 goes into the GELF / `_bulk`
JSON body, `encoding/json` replaces it with U+FFFD, and some inputs reject the
document. Back off to a rune boundary.

## 7. A malformed account id gives up without counting - low

`depin/client.go:371`. The `uuid.FromBytes` failure in `Account` returns a bare
`&Error{...}` rather than `failed(&Error{...})`, so a coordinator answering
with an unreadable account id produces no `depin_call_failed` event, unlike
every other give-up path in the package. The pre-existing `Upload` id path
(`client.go:177`) has the same gap and the new code copied it.

## 8. The Recorder may be more forgiving than the coordinator - low

`depin/depintest/recorder.go:143`. For `offset >= len(body)` the Recorder
returns `nil`: a silent success that writes nothing. The reviewer's claim is
that the real path sends the range on and the coordinator answers
`OutOfRange` - which is what `depin/client.go:227`'s own comment asserts - so a
handler with an off-by-one would pass its Recorder-based test and return an
empty 200 in production.

**Not changed yet, because the premise is unverified.** The SDK clamps with
`effectiveRange(offset, length, manifest.FileSize)` before streaming, so a
range starting past EOF may well come back as an empty success there too. Worth
one call against a dev coordinator: if it answers `OutOfRange`, the Recorder
should return `CodeInvalid` for that case and `DownloadRange`'s doc should say
so.

## 9. `mail`'s new `Unwrap` has nothing to unwrap - low

`mail/mail.go:117`. `Unwrap` was added but `cause` is never assigned anywhere
in the package: the only two constructors are `mail/resend.go:228` and
`mail/mail.go:135`, neither sets it. So `errors.Is`/`errors.As` still cannot
reach a transport error through a `*mail.Error`, contrary to the new doc
comment and to the CHANGELOG entry that lists `mail` beside `depin`, `slack`
and `s3client` - those three do populate `cause`.
