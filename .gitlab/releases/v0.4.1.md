> 🚀 Observability and depin coverage: a log-site call stack
> (`log.stacktrace-level`), a SQL query log (`db.log-queries`,
> `db.slow-query`), three new `depin.Storage` methods, and two real bugs closed

## 1. TL;DR

Three commits of observability and API coverage on top of `v0.4.0`. `logger`
can attach the call stack of the log statement itself, separately from the
error's own stack, and the call site finally reaches the file, Graylog and
Elasticsearch sinks rather than the console alone. `postgres` gained a query
log that never logs bind parameters. `depin` grew the three calls a service
still went to the go-sdk directly for: a byte-range download, a locally signed
download ticket, and an account lookup that returns this module's own struct
instead of a protobuf message full of unnameable types. `lrucache`'s `Add` was
found to grow a cache without bound and to panic when caching was disabled;
both are fixed, and it gained an expiry margin for values that carry their own
expiry.

It is a patch bump because everything is additive or a fix, with the two
caveats in §6: `depin.Storage` is three methods wider, and `Critical` files its
stack under a different field.

## 2. Highlights

### 2.1 `logger`: the call stack of the log statement, and a call site that reaches the sinks

- **`logger.Config.StacktraceLevel` / `log.stacktrace-level`.** Every record at
  or above the configured level carries `callstack` - how the goroutine reached
  the log statement - the way zap's `AddStacktrace` does. Blank, the default,
  disables it and costs nothing.
- This is **not** `stacktrace`. That one says where a failure _began_, comes
  from the error, and only exists when something in its chain is a zeebo/errs
  error. `callstack` says how the process got to the line that reported it and
  exists for any record. Both can appear on one record; Elasticsearch files
  `stacktrace` under ECS `error.stack_trace` and `callstack` under
  `log.origin.stack_trace`.
- The capture happens in the outermost handler - the last point still running on
  the caller's goroutine, since `asyncHandler` hands the record to a consumer
  whose stack is its own loop - and is anchored on the record's own program
  counter, so slog's dispatch and this package's own handlers are dropped
  without encoding how deep either is.
- **`log.origin.file.name` is no longer always absent.** With `AddSource`, the
  console handler computed the caller's `file:line` and passed it to the
  console writer alone; the attribute map handed to the file, Graylog and
  Elasticsearch sinks never got it, so the Elasticsearch sink's `case "source":`
  branch was dead in production and `logger/README.md`'s promise was not kept.
- Where: `logger/callstack.go`, `logger/handler.go`, `logger/critical.go`,
  `logger/elasticsearch.go`, `logging/logging.go`.

### 2.2 `postgres`: a query log that cannot leak a bind parameter

- **`db.log-queries`** logs every statement at debug; **`db.slow-query`** logs
  anything at or over a duration at warn. A failure is an error whatever the
  threshold says, and a slow statement is a warning rather than a warning and a
  debug line. Both are off by default, so a pool nobody configured logs
  nothing.
- **Bind parameters are never logged.** pgx sends them separately from the
  statement, so what is logged is the parameterized form - `WHERE email = $1` -
  and the value that would identify a person stays out of the log.
  `TraceQueryStart` drops `data.Args` rather than carrying them to the logger.
  The statement is collapsed onto one line and capped at 2,048 characters with
  a `...[truncated]` marker.
- **A `group=db` record is mapped to `db.*` in Elasticsearch**:
  `db.statement`, `db.operation`, `db.rows_affected`, `db.instance.name` and
  `event.duration`, the way an api-group record is already split into `http.*`
  and `url.*`. Left in `log.extra` they would be stored but not mapped, so
  "every UPDATE over 200ms" would not be a query anyone could write - which is
  the reason the statement is logged at all. The names follow OpenTelemetry's
  db semantic conventions; ECS has no database fieldset.
- The tracer is now installed for logging as well as for metrics, so
  `metrics: false` no longer turns the query log off with it.
- Where: `postgres/querylog.go`, `postgres/postgres.go`, `postgres/monkit.go`.

### 2.3 `depin`: range download, locally signed ticket, account lookup

- **`DownloadRange(ctx, fileID, w, offset, length)`** writes the plaintext
  bytes `[offset, offset+length)`. A caller that packs thumbnail sizes, HLS
  segments, captions and chapters into one uploaded file reads one back without
  fetching the whole pack. A negative offset or a length of zero or less is
  `invalid` here rather than an `OutOfRange` a round trip later; a whole file
  stays `Download`'s job, so a zero length does not mean "the rest".
- **`CreateLocalTicket(fileID, expiresAt)`** signs a ticket with the identity's
  own CA key and makes no coordinator call, which is what a playlist minting
  one link per segment needs - an RPC per link is what pushed playlist loading
  past client timeouts. It takes no context because nothing about it blocks. An
  identity directory with no `ca.cert`/`ca.key` pair reports `auth`, a distinct
  code so the fallback to `CreateTicket` is a check on `Code` and not a match
  on a message. `Ticket.ExpiresAt` comes back truncated to the second, because
  the token carries whole Unix seconds and that is what the coordinator
  enforces.
- **`Account(ctx)`** returns this module's `Account` - `ID`, `Address` (the
  deposit address, EVM-style hex), `Email`, `Status`, `CreatedAt` - rather than
  the SDK's protobuf record, whose id and address types are declared in
  `go-sdk/internal/vo` and so cannot be named outside that module. It is a
  short idempotent RPC, so it retries with the other coordinator calls. The
  coordinator's `NotFound` for an identity it has no record of means an
  identity that was never registered - what a redeployed coordinator produces -
  which every caller has to treat as an auth failure, so this one call reports
  it as `auth`.
- `depintest.Recorder` serves ranges from `Files` clipped to the recorded
  bytes and records them in `Ranges()`; local tickets are recorded apart from
  coordinator ones in `LocallyTicketed()`, and `AccountRecord` is what
  `Account` returns. The `log` provider reports a range as `not_found` like its
  `Download`, mints the same stand-in token for a local ticket as for a
  coordinator one, and answers `Account` with a stand-in whose address is the
  zero address, so a service that reads its deposit address at startup still
  boots with no identity and no coordinator.
- Where: `depin/depin.go`, `depin/client.go`, `depin/log.go`,
  `depin/depintest/recorder.go`.

### 2.4 `lrucache`: two real bugs, and a margin for values that expire on their own

- **`Add` grew the cache without bound and broke `Capacity`.** When it evicted,
  it deleted the map entry but left the list element in place, so the order
  list grew for every insert and every later eviction picked a key that was
  already gone - which meant nothing was actually evicted and the map grew too.
  A cache with `Capacity: 2` held **99 entries after 99 adds**. `Get`'s own
  eviction path was always correct, so only the `Add`/`GetCached` pair leaked.
- **`Add` panicked when caching was disabled.** A non-positive `Capacity`
  disables the cache, which `Get` has always honored by calling straight
  through, but `Add` read the back of an empty list and dereferenced nil.
- **`Options.EarlyExpiry` and `AddUntil`.** A signed URL, a download ticket or
  an access token expires on its own schedule, whatever the cache's TTL says,
  and handing one out a second before it dies means the caller gets it refused.
  `AddUntil(ctx, key, value, expiresAt)` stores the value's own expiry and
  `EarlyExpiry` is how long before it the entry stops being served. The margin
  is exclusive, `Expiration` still applies on top, and `Get` reads the same
  predicate as `GetCached`, so neither path serves an entry the other would
  refuse.
- Where: `lrucache/cache.go`.

## 3. Added

- **`logger.Config.StacktraceLevel`** / `logging` `log.stacktrace-level`, and
  the `callstack` field (ECS `log.origin.stack_trace`).
- **`postgres.Config.LogQueries` and `Config.SlowQuery`** (`db.log-queries`,
  `db.slow-query`), and the `db.*` / `event.duration` Elasticsearch mapping for
  a `group=db` record.
- **`depin.Storage.DownloadRange`, `CreateLocalTicket`, `Account`** and the
  `depin.Account` struct, plus `depintest.Recorder.Ranges`,
  `LocallyTicketed`, `AccountRecord` and `depintest.Range`.
- **`errors.Unwrap` on `depin`, `slack`, `s3client` and `mail` errors.** Each
  `*Error` gains an `Unwrap`, so `errors.Is` reaches a `context.Canceled`, an
  `io` error or the SDK's typed error through a failure instead of finding it
  flattened into the message string. The `*Error` is still what a caller
  matches with `errors.As`.
- **`lrucache.Options.EarlyExpiry` and `lrucache.AddUntil`.**

## 4. Changed

- **`depin.Storage` is three methods wider.** Anything outside this repo
  implementing it needs `DownloadRange`, `CreateLocalTicket` and `Account`;
  `depintest.Recorder` and the `log` provider already have them.
- **`Critical` attaches its stack as `callstack`, not `stacktrace`,** and
  `logger.Stack()` returns the same trimmed `function:line` shape as every
  other stack this package prints instead of its own
  `function\n\tfile:line` one. Before, a `Critical` about an error overwrote
  that error's `stacktrace` with its own call stack, so the failure's origin
  was lost exactly where it was most wanted, and a `Critical` with no error
  filed a call stack as `error.stack_trace`.
- **The go-sdk pin moves to `v0.0.0-20260921104014-ef2115da4a3b`** (`ef2115d`),
  which is where `DownloadFileRange`, `CreateDownloadTicketLocal` and
  `GetAccount` live.
- **The pgx tracer is installed whenever logging or metrics is on.** It used to
  be installed for metrics only, so `metrics: false` silently disabled the
  query log too.

## 5. Fixed

- **`log.origin.file.name` was always absent.** The call site reached the
  console writer only; the file, Graylog and Elasticsearch sinks never got it,
  which left the Elasticsearch sink's `source` branch dead in production. A
  record that logs its own `source` - the source of a payment, a feed - keeps
  it.
- **`lrucache.Add` grew the cache without bound and broke `Capacity`** (see
  §2.4). Eviction now takes the key out of both halves and repeats until there
  is room, and replacing an existing key no longer evicts a different one to
  make space for it.
- **`lrucache.Add` panicked when caching was disabled.** It now stores nothing
  and reports `replaced` as false.
- **`postgres`'s bind-parameter leak test failed on the clock.** It asserted
  the formatted records did not contain `42`, the non-string parameter, and two
  digits turn up inside a measured duration (`1.000421ms`) or a timestamp
  (`17:58:00.260342962`) often enough to fail a clean run. The parameter is now
  long and distinctive and the assertion reads the message and attributes
  without the wall-clock time.

## 6. Migration notes

- **The `db.*` log mapping needs the paired `aioz-monitor` index template.**
  The template must gain `db.*` and `log.origin.stack_trace`. Without it, a
  query log record's fields are dynamically mapped like anything else and
  "every UPDATE over 200ms" is not a query anyone can write. **Ship the two
  together.**
- **Anything querying `error.stack_trace` for `Critical` lines must move to
  `log.origin.stack_trace`.** A `Critical`'s call stack is now `callstack`;
  `error.stack_trace` carries the error's own origin only.
- **Anything outside this repo implementing `depin.Storage` must add
  `DownloadRange`, `CreateLocalTicket` and `Account`.** Strictly, widening an
  exported interface is a breaking change; it is shipped as a patch because
  every known implementation lives in this module (`Client`, the `log`
  provider, `depintest.Recorder`). A consumer that only _calls_ `Storage` needs
  no change.
- **`CreateLocalTicket` needs `ca.cert` and `ca.key` in the identity
  directory.** Without them it fails with `CodeAuth` on every call, which is
  the signal to fall back to `CreateTicket` - so a deployment that never
  provisioned the CA pair silently keeps paying one coordinator RPC per link.
  Check the code, never the message.
- **Upgrading the go-sdk pin does not change the `replace` requirement.**
  Importing `depin` still needs `replace github.com/gogo/protobuf =>
github.com/regen-network/protobuf v1.3.3-alpha.regen.1` in the consuming
  module's `go.mod`, and a post-split `genproto`. See `v0.4.0` §6.
- **`db.log-queries` at debug is per-statement volume.** Leave it off in
  production and use `db.slow-query` (e.g. `200ms`) instead; the statement is
  capped at 2,048 characters but the line count is not.
- **`lrucache` consumers get the eviction fix for free, and it changes memory
  behavior**: a cache that was quietly holding far more than `Capacity` will now
  hold `Capacity`. If anything depended on the old over-retention as a cheap
  "unbounded cache", set `Capacity` to what it actually needs.
