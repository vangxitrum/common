# Release v0.4.0

> 🚀 Four new packages (`s3client`, `depin`, `slack`, `proclock`), a metrics
> push path (`stats/telemetry`) and an Elasticsearch log sink. Consumer action
> required: see §6 (Migration notes) before upgrading - importing `depin` needs
> a `replace` directive in the consuming module, and the Elasticsearch sink
> only works paired with the matching `aioz-monitor` index template.

## 1. TL;DR

Object storage (`s3client`), depin network storage (`depin`), Slack
notifications (`slack`) and a single-instance process lock (`proclock`) all
move out of the services and into this module. Metrics can now be *pushed*
(`stats/telemetry`, Prometheus remote_write) as well as scraped, and logs can
be shipped to Elasticsearch. It is a minor bump because it is almost entirely
additive, with three exceptions: `logging.Config` gains an `Elasticsearch`
block whose `IndexFields` means the opposite of Graylog's, `depin` imposes a
`replace` directive on every consumer's `go.mod`, and the module's transitive
dependency set grows a great deal (libp2p, the AWS SDK, grpc).

## 2. Highlights

### `s3client`: one S3 client that works against our own storage

- Replaces the three divergent copies in `aioz-stream`, `aioz-map` and
  `crawler-service`. Our service is not AWS, and since aws-sdk-go-v2 v1.72 the
  SDK computes a CRC32 for every request by default, turning a streaming body
  into `aws-chunked` with a trailing checksum. Our server rejects all of it.
  So request and response checksums are set to *when required*, path style is
  forced, and `DeleteObjects` gets the `Content-MD5` its protocol defines from
  a middleware that **swaps** the SDK's checksum middleware rather than adding
  one - swapped, it inherits that middleware's position before SigV4 signs, so
  the header lands in `SignedHeaders`.
- The setting is applied to the uploader as well as the client. Uploads go
  through `feature/s3/transfermanager` (the SDK deprecated
  `feature/s3/manager`), whose own checksum setting **takes precedence over**
  the client's, so getting it wrong there is worse than before. Downloads stay
  on the plain `*s3.Client`: transfermanager's `GetObject` always issues ranged
  GETs from a goroutine pool and hands back a body with no `Close`.
- `Client` embeds `*s3.Client` rather than hiding it behind an interface: it
  has ~90 methods and we wrap nine. `Config.Compat` names the server, `aioz` by
  default or `aws`. The package deliberately never calls
  `config.LoadDefaultConfig`, so `~/.aws`, the `AWS_*` environment, SSO and the
  EC2 metadata service cannot change what a service talks to.
- Old bugs closed rather than carried: the uploader is built once in the
  constructor (8MiB × 4 parts, not 100MB × 5), `Get` returns an `*Object` whose
  `Body` is an `io.ReadCloser`, a missing object is `CodeNotFound` (not a
  `false` that also swallowed an expired credential), the startup check is
  `HeadBucket` not a `ListBuckets` scan, and every method takes the caller's
  context instead of `context.Background()` with a 90-second timeout.
  `httpclient`'s 32MiB response cap and 30s request backstop are off here -
  both are right for an API and would truncate a download.
- Surface: `s3client.New`, `Client`, `Config`, `Object`, `Error`, `IsNotFound`.
  See [`s3client/README.md`](../../s3client/README.md).

### `stats/telemetry`: push metrics instead of waiting to be scraped

- A Prometheus remote_write client that walks a monkit registry on an interval
  and POSTs the series to VictoriaMetrics, Cortex, Mimir or Prometheus's own
  receiver. It is the push counterpart to the pull-based `/metrics` in
  `stats/debug`: that endpoint serves since-last-scrape deltas, this one always
  reports raw cumulative values, because remote_write receivers expect
  monotonic counters and compute `rate()` themselves.
- Off by default - an empty `URL` disables it. Every series carries `app`,
  `instance`, `role` and, when set, `env`; an empty `env` is dropped entirely
  so a service that has not been told its environment pushes exactly what it
  pushed before. `instance` resolves to the hostname or container id once at
  construction, so replicas get distinct identities with no extra config.
- Cardinality is bounded at the source: `DropQuantiles` (on by default) drops
  monkit's per-call-site reservoir fields (`r10`/`r50`/`r90`/`r99`/`rmin`/`rmax`)
  while keeping count/sum/min/max/recent, and `IncludePrefixes` /
  `ExcludePrefixes` filter by measurement name.
- `WithGatherer` / `IncludeDefaultGatherer` also push everything registered
  with prometheus/client_golang, for services instrumented with both.
- The protobuf is hand-written (`remotewrite.go`) - the wire format is four
  message types, and the alternative is the whole Prometheus module.
- Surface: `telemetry.NewClient`, `Client.Run`/`Close`, `Config`,
  `WithGatherer`, `WithHTTPClient`.

### Logs to Elasticsearch, with a bounded field mapping

- `logger`'s new batching bulk sink ships records to a data stream.
  `logging.ElasticsearchConfig` configures it: `URL`, `DataStream`, auth
  (bearer token, API key or basic), `BatchSize`, `FlushInterval`, `Timeout`.
  It does not retry - a flush that fails is dropped, deliberately, rather than
  turning a log line into a queue with unbounded memory behind it.
- **A service now declares which attributes Elasticsearch indexes.** A declared
  attribute goes where ES maps it (`labels.<name>` or an ECS field); every
  other attribute goes to `log.extra`, which the index template maps with
  `"enabled": false`. Both are shipped and both are in `_source`, so nothing is
  lost from Discover - the undeclared half simply adds no field to the mapping
  and cannot be filtered or aggregated on. That is the point: a mapped field
  stays in the mapping for ever, and an index has a field limit (1000 by
  default) that a service inventing attribute names at runtime reaches on its
  own.
- `log.elasticsearch.role` is stamped on every document as `service.role` -
  what this process does (`api`, `worker`, `job-runner`) - so a service
  deployed as several of them can be told apart. It is process configuration
  rather than a per-record attribute because a value that can be forgotten at a
  call site will be.
- `source`, `error`, the stack trace and `trace_id` are always written where
  ECS puts them whether or not they were declared: they describe the event, not
  a dimension of it.

### `depin`, `slack`, `proclock`

- **`depin`** - files stored and fetched through the depin network behind a
  provider-neutral `Storage`. The go-sdk is wrapped rather than used directly:
  its identifiers live in `go-sdk/internal/vo`, out of reach of every other
  module, so ids cross the boundary as `[]byte` and become `uuid.UUID`; and it
  reports every failure as a formatted string, so failures are classified from
  the gRPC status underneath into an `*Error` whose `Code` and `Temporary` say
  whether retrying could help. Only the short coordinator calls are retried -
  an upload's reader cannot be rewound, and the SDK already retries its own
  download pieces. A `log` provider stores nothing, for dev and CI, and
  `depin/depintest` holds a recording fake.
- **`slack`** - messages posted to the Web API through a provider-neutral
  `Notifier`. `chat.postMessage` answers **200** with `{"ok": false}` for
  almost every failure, a missing channel and a revoked token included, so a
  client that reads the status code reports those as delivered. Here the body
  decides first and the status second. A rate limit's `Retry-After` is honored
  unless it exceeds `httpclient.MaxRetryAfter`. No vendor SDK and no
  idempotency key: only failures known not to have posted are retried, because
  Slack offers no way to make a repeat harmless. The bot token is a
  `secret.Token`, and no message text or block reaches a log line.
- **`proclock`** - `Acquire(config, name)` takes an flock on a file held open
  for the life of the process, so a second copy of a service cannot start on
  the same machine. The kernel releases it when the process dies, SIGKILL and
  panic included, so there is no heartbeat, no timeout and no stale-lock
  recovery. It is explicitly **not** a distributed lease: it says only "not
  twice on this box".

## 3. Added

- **`s3client`** - `New`, `Client`, `Config` (with `Compat`), `Object`,
  `ObjectInfo`, `PutParams`, `ListParams`, `Page`, `DeleteParams`,
  `CopyParams`, `Error`, `Code`, `IsNotFound`, `IsPrecondition`,
  `IsTemporary`, `All`.
- **`stats/telemetry`** - `NewClient`, `Client`, `Config`, `Option`,
  `WithGatherer`, `WithHTTPClient`, `Config.Enabled`.
- **`depin`**, **`depin/depintest`** - `Storage`, `New`, `NewLog`, `Config`,
  `Client`, `NewClient`, `ClientConfig`, `Placement`, `UploadParams`,
  `Receipt`, `Ticket`, `Error`, and the `depintest` recorder.
- **`slack`**, **`slack/slacktest`** - `Notifier`, `New`, `NewSlack`,
  `NewLog`, `Config`, `Client`, `NewClient`, `ClientConfig`, `Message`,
  `Receipt`, `Error`, and the `slacktest` recorder.
- **`proclock`** - `Acquire`, `Lock`, `Config`, `HeldError`, `ErrHeld`,
  `MaxNameLen`, `Lock.Path`.
- **`logger/logtest`** - `New(t)` writes every record into the test's own log,
  so a failing test prints what the code under test logged and a passing one
  prints nothing. `NewRecorder` keeps every record - message, level, attributes
  flattened to dotted keys, errors kept as errors - which is what zap's
  `zaptest/observer` was used for.
- **`logger` Elasticsearch sink** and `logging.ElasticsearchConfig`,
  `logger.DefaultIndexFields`.
- **Per-component levels** - `logger.Config.ComponentLevels` and
  `logging.Config.CustomLevel` (`audit=warn,relay=error`). A record whose
  `component` attribute names a listed component is written only at or above
  that component's level, so one noisy part of a service can be quietened
  without losing the rest of its debug output. The innermost component wins.
  `logging.ParseCustomLevel` parses the spec.
- **`logging.Config.Output`** - stdout, stderr or a file path for the console
  format; `logger.Config.Output` / `logging.WithOutput` take a writer directly.
- **`stats/debug.NewServerWithLevelHandler`** - serves `/logging` from any
  `http.Handler`, for a process whose level does not live in an
  `*slog.LevelVar`. `NewServerWithLevel` is now a wrapper over it.
- **`httpclient.ConfigureH2HealthChecks`** plus
  `DefaultH2HealthCheckInterval` (15s) and `DefaultH2PingTimeout` (5s), and
  `Config.H2HealthCheckInterval` / `Config.H2PingTimeout`.
- **`errs2.Origin` and `errs2.Frames`** - the innermost zeebo/errs error in a
  chain and its stack as a `[]string`, through `fmt.Errorf("%w")` and `apierr`,
  and for untagged `errs.Errorf` too.
- **`logger.ErrorStack`, `logger.FormatStack`, `logger.ErrorAttr`** - the same
  pieces for a handler built on `slog.TextHandler`. `ErrorStack` trims frames
  (host and owner dropped; runtime, errgroup and lifecycle frames left out).
- **`config.FindConfigDirParam`, `FindIdentityDirParam`, `FindDefaultsParam`** -
  the three flags a service reads out of `os.Args` before flag parsing has
  happened, so a default that expands `$CONFDIR` can be built while the flags
  are still being declared.

## 4. Changed

- **HTTP/2 dead-connection detection.** Go disables HTTP/2 health checks by
  default (`HTTP2Config.SendPingTimeout` is zero). A connection broken without
  a TCP reset - an expired NAT entry, a middlebox dropping the flow, a tunnel
  restarting - stays in the pool looking healthy, and every request multiplexed
  onto it hangs until its own deadline. `httpclient`'s pooled `Transport` now
  pings an idle h2 connection every 15s and closes it if no pong arrives within
  5s. `OneShotTransport` leaves health checks off - it disables keep-alives
  entirely. The telemetry push client turns them on too: it reuses one
  connection, so a dead one was a total metrics blackout, not one stalled call.
- **`logging.Config` gains an `Elasticsearch` block.** Any consumer that
  encodes or diffs its config file sees new keys.
- **`Elasticsearch.IndexFields` is not `GraylogConfig.IndexFields`.** Empty now
  means `logger.DefaultIndexFields` (`service`, `role`), where in the Graylog
  sink empty means "index everything" and a listed set *drops* the rest. Here
  nothing is dropped; the list decides indexed-vs-stored only.
  `GraylogConfig.IndexFields` is unchanged.
- **`logging.Config.Validate` rejects an Elasticsearch URL with no scheme.** It
  used to bind, build a sink, then fail once per flush at the transport with
  nothing pointing back at the configuration.
- **`ElasticsearchConfig.URL` and `BearerToken` are no longer flags**
  (`noflag:"true"`). They come from the config file or the environment - a
  bearer token on a command line is readable by every process on the host.
- **`depin` hands the go-sdk the caller's `*slog.Logger` directly.** The go-sdk
  now logs through `log/slog`, so the zap core that bridged its lines is gone
  and this module no longer imports zap anywhere. It stays in `go.mod` only as
  an indirect dependency of libp2p.
- **The text console names a source as `pkg/file.go:line`**, not the absolute
  path of whatever checkout built the binary. JSON output and the sinks keep
  the full path.
- **`errs2.Frames` reads a zeebo/errs v1 error too.** It matched the v2 type
  alone, so a service part-way through the move between them got no frames from
  half its errors - and with no frames `logger.ErrorStack` logs nothing and
  `error.stack_trace` is empty.
- **Dependencies** - new direct: the AWS SDK v2 (`aws-sdk-go-v2`,
  `credentials`, `service/s3`, `feature/s3/transfermanager`, `smithy-go`),
  `prometheus/client_golang` + `client_model`, `golang/snappy`,
  `gitlab.internal/aioz-depin/go-sdk`, `google.golang.org/grpc`,
  `golang.org/x/net`, `zeebo/errs` v1 (alongside v2). Bumped: `x/crypto`
  v0.55.0 → v0.57.0, `x/sync` v0.22.0 → v0.23.0, `x/text` v0.41.0 → v0.42.0,
  monkit to a v3.0.25 pre-release. The go-sdk pulls libp2p and its tree in as
  indirect dependencies.

## 5. Fixed

- **`logger` logs an error as its message, with a stack you can read.** The
  console handler wrote an error attribute with `%v`, which dropped the
  zeebo/errs stack; `json.Marshal` - used by the JSON console, the file sink
  and Graylog - wrote it as `{}`, because zeebo/errs's error has no exported
  fields. Now `err` is the message and the stack of where the error began is
  `stacktrace`, one trimmed `function:line` per line. The cause of an `apierr`
  counts. `Critical`'s call-site stack still wins, and on the console every
  stack block is labeled `stack:` and indented under the line.
- **Metric pushes no longer black out on a dead connection** - see §4.

## 6. Migration notes

- **Importing `depin` requires a `replace` directive.** A consuming module
  needs `replace github.com/gogo/protobuf =>
  github.com/regen-network/protobuf v1.3.3-alpha.regen.1` in its own `go.mod`.
  Go ignores a `replace` declared by a dependency, and the go-sdk requires one
  for a `gogo/protobuf` version that does not exist upstream, so without it the
  build fails with `unknown revision v1.3.3` **even in a service that never
  touches this package**.
- **That replacement needs a post-split `genproto`.** The pre-split
  `google.golang.org/genproto` carries `googleapis/api` packages that also live
  in the split-out `genproto/googleapis/api` newer grpc requires, so `go mod
  tidy` stops with `ambiguous import` wherever something pulls in grpc-gateway,
  as OpenTelemetry does. This module now requires `genproto` at a post-split
  version. A consumer that hits the same error fixes it the same way.
- **The Elasticsearch sink needs the paired `aioz-monitor` index template.**
  The template must gain `log.extra` (`"enabled": false`) and `service.role`.
  Without it, `log.extra` is dynamically mapped like anything else and the
  field count is no more bounded than before. Ship the two together.
- **Dashboards filtering on an undeclared attribute stop matching.** List it in
  `log.elasticsearch.index-fields`. The attribute is still visible in the
  document meanwhile - only filtering and aggregation are affected.
- **Set `log.elasticsearch.role`** per deployment (`api`, `worker`, ...), or
  every process of a service looks the same in Discover.
- **`telemetry` is off until `URL` is set.** When enabling it, set `app`,
  `role` and `env`; `env` should match the `AIOZ_ENV` the host agent uses on
  the same machine, so app series and node_exporter series for one deployment
  can be selected together.
- **`s3client` callers must close `Object.Body`.** It is an `io.ReadCloser` by
  design; the copies it replaces handed back a bare `io.Reader`.
- **`proclock.Config.Dir` defaults to `$CONFDIR/run`** - make sure that path is
  writable, and not on a filesystem where flock is a no-op (some network
  mounts).
- **Upgrading the module** pulls the AWS SDK, prometheus/client_golang and, if
  `depin` is imported, libp2p and grpc into the service's `go.mod`. Run
  `go mod tidy` and expect the dependency graph to grow.

## 7. Internal

- `logger/zapbridge` was added (`a0db874`) and removed again (`aaa09da`) inside
  this same range. The go-sdk moved to `log/slog`, which was the only thing the
  bridge existed for, so the module now imports zap nowhere. Anything that
  observed zap records in tests uses `logger/logtest.NewRecorder` instead.
- CI now sources its shared jobs from `aioz-ci-template` rather than keeping
  its own copies (`.gitlab-ci.yml`, -142/+142).
- Private Go modules are enabled for the build (GOPRIVATE/GOINSECURE for
  `gitlab.internal`), which `depin` needs.
- The remote_write protobuf is hand-written rather than generated: the wire
  format is four message types and the alternative is depending on the whole
  Prometheus module.
